# 26.5.0 Office Engine Feasibility Research

Status: research only. This branch is based on the accepted 26.4.3 release and must not change the stable release branch.

## Product constraints

- Target device: HERAN HD-50UDF26
- Android 5.0.1 / API 21
- ARM64 (AArch64), 2 GB RAM
- One offline APK, maximum target size 1 GB
- TV remote / D-pad operation
- Keep the existing OldTV Revival launcher and file manager
- Prioritize broad DOCX, XLSX and PPTX editing capability

## Candidate: Collabora Office / LibreOffice engine

### Evidence found

1. Collabora's Android release information states Android 5.0 or later as the required OS:
   https://www.collaboraonline.com/collabora-office-android-ios-release-notes/
2. Collabora's Android build guide says native parts are built on Linux or macOS, the engine is built before the Android app from the same monorepo, and the engine requires Android NDK 27 or later:
   https://www.collaboraoffice.org/post/build-code-android/
3. The same build guide lists arm64-v8a as a supported Android ABI and describes a dedicated CPAndroidAarch64 engine build.
4. Google Play's Collabora Office description says the Android app uses the LibreOffice engine, with a Collabora Online-derived front end, and supports common ODF and Microsoft Office formats. It lists the license as MPL 2.0 and other licenses:
   https://play.google.com/store/apps/details?id=com.collabora.libreoffice
5. Collabora's October 2026 mobile article says the app runs locally and supports editing locally available documents offline:
   https://www.collaboraonline.com/blog/collabora-office-for-mobile-26-04-a-smaller-screen-bringing-more-power/

## Preliminary assessment

- OS/ABI: promising, but the exact current mobile release's minimum SDK and native-library compatibility must be verified against API 21 before integration. A general product page saying Android 5+ is not sufficient proof that every current build works on Android 5.0.1.
- Build: substantial. The native engine build is a separate, heavy Linux/macOS toolchain step; it is not a normal Gradle dependency that can simply be added to the current Android project.
- Integration: not yet proven. The official guide documents building the Collabora Android app from its monorepo; it does not document embedding the full editor as a library inside an unrelated APK. We need to evaluate either merging its Android app/front-end into OldTV Revival or adapting the Collabora app shell while preserving OldTV's launcher and file manager.
- Offline: supported for local documents according to Collabora's mobile documentation.
- License: MPL 2.0 and other component licenses are reported by the app listing. Before redistribution, preserve notices and audit all bundled component licenses and obligations.
- TV UX: keyboard/touch-oriented UI may need focus and D-pad adaptation. Actual remote testing is required.
- Memory: 2 GB RAM is a major risk. Test large DOCX/XLSX/PPTX documents and cold-start memory use on the real TV.
- APK size: the 1 GB ceiling appears generous relative to historical mobile package sizes, but the final merged APK and native libraries must be measured. Do not assume the limit is met until a release artifact is built.

## Required proof-of-concept gates

1. Identify the exact current Collabora mobile source revision and Android minSdk.
2. Build arm64-v8a native engine and mobile app in Linux CI using the documented toolchain.
3. Confirm that the produced APK installs and launches on API 21, or determine the minimum source changes needed.
4. Verify local offline opening, editing, saving and reopening of DOCX, XLSX and PPTX.
5. Test Chinese text/fonts, images, tables, spreadsheet formulas and presentation layouts.
6. Test D-pad/remote navigation, focus visibility, Back behavior and TV landscape layout.
7. Measure APK size, install footprint, startup time and peak RAM on the target TV.
8. Complete license/notice review before bundling or redistribution.

## Decision

Do not replace the 26.4.3 release or merge the engine into the production app yet. Continue with an isolated proof of concept. The preferred direction remains OldTV Revival launcher/file manager + Collabora/LibreOffice editing engine, subject to passing all compatibility and performance gates.
