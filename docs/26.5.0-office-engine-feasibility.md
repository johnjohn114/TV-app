# 26.5.0 Office Engine Feasibility Research

Status: research / isolated proof-of-concept planning only. This branch is based on the accepted 26.4.3 release and must not change the stable release branch.

## Product constraints

- Target device: HERAN HD-50UDF26
- Android 5.0.1 / API 21
- ARM64 (AArch64), 2 GB RAM
- One offline APK, maximum target size 1 GB
- TV remote / D-pad operation
- Keep the existing OldTV Revival launcher and file manager
- Prioritize broad DOCX, XLSX and PPTX editing capability

## Candidate A: current Collabora Office mobile source

### Verified source configuration

- Inspected the public read-only source mirror: https://github.com/CollaboraOnline/online.mirror
- Current `main` branch `android/app/build.gradle` explicitly sets `minSdk 26`, `targetSdk 37`, compile SDK 37 and NDK 29.0.14206865.
- The older `distro/collabora/co-25.04` branch also explicitly sets `minSdk 26` (compile SDK 36, target SDK 35, NDK 28.2.13676358).
- Therefore, current Collabora Android app shell does not directly target this TV's API 21. Lowering minSdk alone would not prove compatibility: AndroidX dependencies, Java APIs, native library API level and runtime behavior still need audit.
- The public source mirror is read-only; upstream development is hosted on Collabora Gerrit.

### Build and integration

1. Collabora's Android build guide says native parts are built on Linux or macOS, the engine is built before the Android app from the same monorepo, and the engine requires Android NDK 27 or later.
2. The guide lists arm64-v8a as supported and describes the CPAndroidAarch64 engine build.
3. The official guide documents building the Collabora Android app from its monorepo. It does not document embedding the full editor as a library in an unrelated APK.
4. The Android app currently depends on AndroidX UI libraries and a project-local `:lib` module, so integration is more than adding a single AAR dependency.

## Candidate B: current LibreOffice Android app / core

### Verified architecture

- Inspected the current `LibreOffice/core` Android source.
- `android/README.md` says the Android app bundles the LibreOffice core in one shared library named `liblo-native-code.so`, uses LibreOfficeKit (LOK) JNI classes, and renders document tiles using OpenGL ES 2.
- The README documents a multi-thread design for UI, OpenGL rendering, LibreOfficeKit calls and the native LibreOffice core.
- The current Android Gradle project contains two product flavors: `strippedUI` with editing disabled, and `strippedUIEditing` with `ALLOW_EDITING=true`.
- The current Gradle file reads `androidMinSdkVersion` from generated build settings. The native configure step sets `ANDROID_API_LEVEL`, which is used for the NDK target.
- Source code contains DPAD key mapping/forwarding: `LOKitTileProvider.java` maps Android DPAD key events to LibreOffice key events, and `LOKitInputConnectionHandler.java` forwards keyboard events to the engine. This is encouraging but does not prove the entire UI is TV-friendly or has visible focus states.

### Strong API-21 build evidence

- F-Droid Monitor's reproducible build log for LibreOffice Viewer build 123 / version 26.2.5.2 shows:
  - configure selected Android API level 21;
  - native compiler target was `aarch64-linux-android21`;
  - NDK was 29.0.14206865;
  - Gradle ran `assembleStrippedUIEditingRelease`;
  - the editing-enabled APK packaging task completed and the build reported `BUILD SUCCESSFUL`.
- This is much stronger than the store listing alone: current LibreOffice core and the editing-enabled Android app flavor have been built together for API 21 / ARM64 in a reproducible external build.
- It still does not prove runtime operation on the HERAN TV, 2 GB RAM performance, or complete D-pad usability. The published F-Droid listing describes the app as a viewer and labels editing experimental.

## Cross-cutting assessment

- OS/ABI: current LibreOffice's native engine and editing-enabled Android flavor have reproducible API-21 / ARM64 build evidence. Current Collabora app shell remains configured for API 26.
- Editing: LibreOffice source includes an editing-enabled flavor and F-Droid's API-21 build log proves it packages successfully. Production editing quality still requires real-document tests.
- Offline: the Android app is built around local document access; real offline tests are still required.
- TV UX: some DPAD key handling exists, but document browser, toolbars, dialogs and edit controls may still be touch-oriented. Full remote navigation and visible focus need adaptation.
- Memory: 2 GB RAM is a major risk. Test cold start and representative documents on the real TV.
- APK size: F-Droid's arm64 Viewer package is listed at about 83 MiB. A merged APK may be larger; measure the actual output.
- License: LibreOffice Viewer is listed under MPL 2.0. Preserve notices and audit every bundled component before redistribution.

## Updated proof-of-concept plan

1. Keep 26.4.3 stable and isolate all experiments on `research/26.5.0-office-engine`.
2. Pin the exact F-Droid source revision from build 123 (`cd7284b4cbbfeb507e630c1aac019f4157393acb`) and reproduce the `strippedUIEditing` ARM64/API-21 build in an isolated CI job.
3. Inspect the build metadata and app manifest/dependency graph to identify which app-shell libraries and activities are practical to reuse in OldTV Revival.
4. Produce a standalone API-21 ARM64 proof-of-concept APK first. Test install, launch, offline open/edit/save/reopen for DOCX, XLSX and PPTX on the actual TV.
5. Test Chinese text/fonts, images/tables, formulas, slide layouts, D-pad navigation, focus visibility, Back behavior, RAM, startup time and app stability.
6. Only after standalone API-21 proof, prototype a single-APK merge while preserving the OldTV Revival launcher and file manager. Do not simply launch a separate installed app as the final solution.
7. Complete license/notice review before bundling or redistribution.

## Decision

The current LibreOffice Android source's `strippedUIEditing` flavor is now the leading candidate. A reproducible F-Droid build proves the current ARM64 native core and editing-enabled app flavor can compile/package for API 21 with NDK 29. The remaining blockers are runtime testing on the user's Android 5.0.1 TV, 2 GB RAM behavior, full remote usability, and single-APK integration. Do not replace 26.4.3 or claim 26.5.0 is ready until these gates pass.
