# 26.5.0 Office Engine Feasibility Research

Status: research / isolated proof-of-concept planning only. This branch is based on the accepted 26.4.3 release and must not change the stable release branch.

## Product constraints

- Target device: HERAN HD-50UDF26
- Android 5.0.1 / API 21
- ARM64 (AArch64), 2 GB RAM
- One offline APK, maximum target size 1 GB
- TV remote / D-pad operation
- Keep the existing OldTV Revival launcher and file manager
- Prioritize broad DOCX, XLSX and PPTX editing capability

## Candidate A: current Collabora Office mobile source

### Verified source configuration

- Inspected the public read-only source mirror: https://github.com/CollaboraOnline/online.mirror
- Current `main` branch `android/app/build.gradle` explicitly sets `minSdk 26`, `targetSdk 37`, compile SDK 37 and NDK 29.0.14206865.
- The older `distro/collabora/co-25.04` branch also explicitly sets `minSdk 26` (compile SDK 36, target SDK 35, NDK 28.2.13676358).
- Therefore, current Collabora Android app source does not directly target this TV's API 21. Lowering minSdk alone would not prove compatibility: AndroidX dependencies, Java APIs, native library API level and runtime behavior still need audit.
- The public source mirror is read-only; upstream development is hosted on Collabora Gerrit.

### Build and integration

1. Collabora's Android build guide says native parts are built on Linux or macOS, the engine is built before the Android app from the same monorepo, and the engine requires Android NDK 27 or later.
2. The guide lists arm64-v8a as supported and describes the CPAndroidAarch64 engine build.
3. The official guide documents building the Collabora Android app from its monorepo. It does not document embedding the full editor as a library in an unrelated APK.
4. The Android app currently depends on AndroidX UI libraries and a project-local `:lib` module, so integration is more than adding a single AAR dependency.

## Candidate B: current LibreOffice Android app / core

### Verified architecture

- Inspected the current `LibreOffice/core` Android source.
- `android/README.md` says the Android app bundles the LibreOffice core in one shared library named `liblo-native-code.so`, uses LibreOfficeKit (LOK) JNI classes, and renders document tiles using OpenGL ES 2.
- The README documents a multi-thread design for UI, OpenGL rendering, LibreOfficeKit calls and the native LibreOffice core.
- The current Android Gradle project contains two product flavors: `strippedUI` with editing disabled, and `strippedUIEditing` with `ALLOW_EDITING=true`. This means editing code exists in the current source tree, even though the F-Droid Viewer build is presented as a viewer and editing is experimental.
- The current Gradle file reads `androidMinSdkVersion` from generated build settings. The source build script populates it from `ANDROID_API_LEVEL`; the exact API level used for the current F-Droid build still needs to be confirmed from its reproducible build recipe. Do not assume that the current source automatically builds for API 21.
- D-pad evidence: `LOKitTileProvider.java` maps Android DPAD key events to LibreOffice key events, and `LOKitInputConnectionHandler.java` forwards keyboard events to the engine. This is encouraging, but does not prove that the entire UI is TV-friendly or has visible focus states.

Sources:

- https://github.com/LibreOffice/core/blob/master/android/app/build.gradle.kts
- https://github.com/LibreOffice/core/blob/master/android/app/src/main/AndroidManifest.xml

### F-Droid build facts and limitation

- F-Droid lists LibreOffice Viewer 26.2.6.3 for arm64-v8a, requiring Android 5.0 or newer, with an APK size of about 83 MiB.
- It supports ODF and Microsoft Office formats including DOCX, XLSX and PPTX.
- Important limitation: F-Droid describes it as a viewer; editing is experimental and explicitly not considered production-ready. It is therefore a useful API-21/ARM64 compatibility reference and possible rendering-engine research candidate, but not yet a suitable complete editing replacement.
- The current source has an editing-enabled flavor, but this is not sufficient evidence that the official F-Droid package includes production-ready editing or that all editing flows work on the target TV.

Sources:
- https://f-droid.org/packages/org.documentfoundation.libreoffice/
- https://f-droid.org/en/packages/org.documentfoundation.libreoffice/

## Candidate C: historical Collabora Office

- Historical Collabora Office 6.4.14 (2021) was listed for Android 5.0+ / API 21 and arm64-v8a.
- Historical Collabora Office 4.2.11 was also listed for Android 5.0+ / API 21 and was a roughly 277 MiB universal package.
- Collabora's own 2019 Android beta article stated Android 5.0 as the minimum and described document editing, including text and table editing.
- This shows that a LibreOffice-based Android editor previously targeted API 21. However, these historical app versions are not recommended as the final engine: their old core, security/format support, toolchain and compatibility with current Android libraries need a separate audit. They are research evidence only, not a release recommendation.

## Cross-cutting assessment

- OS/ABI: current Collabora app source is blocked by minSdk 26. Current LibreOffice Viewer is listed as Android 5+ and arm64, but the exact source build API setting must be traced.
- Editing: LibreOffice's source includes an editing-enabled flavor; its maturity and API-21 compatibility remain unverified. This is the strongest source-level candidate so far.
- Offline: Collabora documentation describes local document editing; LibreOffice Viewer is a local document app. Real offline testing is still required.
- TV UX: LibreOffice source has some DPAD key forwarding/mapping, but no source evidence yet that document browser, toolbars, dialogs and edit controls are all usable with a TV remote. Focus and landscape behavior must be tested.
- Memory: 2 GB RAM is a major risk. Test cold start and representative documents on the real TV.
- APK size: F-Droid's arm64 Viewer package is listed at about 83 MiB; historical Collabora universal packages were much larger. The final merged APK must be measured.
- License: LibreOffice Viewer is listed under MPL 2.0. Collabora is MPL 2.0 plus other component licenses. Preserve notices and audit every bundled component before redistribution.

## Updated proof-of-concept plan

1. Keep 26.4.3 stable and isolate all experiments on `research/26.5.0-office-engine`.
2. Trace the exact F-Droid reproducible build recipe and `ANDROID_API_LEVEL` used for the current LibreOffice arm64 build.
3. Build the current LibreOffice `strippedUIEditing` flavor for arm64 in isolated Linux CI, first using the official supported configuration. Do not lower API settings until native and Java dependencies have been audited.
4. If API 21 is confirmed feasible, produce a standalone test APK first. Test install, launch, offline open/edit/save/reopen for DOCX, XLSX and PPTX on the actual TV.
5. Test Chinese text/fonts, images/tables, formulas, slide layouts, D-pad navigation, focus visibility, Back behavior, RAM, startup time and app stability.
6. Only after standalone API-21 proof, prototype a single-APK merge while preserving the OldTV Revival launcher and file manager. Do not simply launch a separate installed app as the final solution.
7. Complete license/notice review before bundling or redistribution.

## Decision

Do not lower the current Collabora minSdk by changing one number, do not merge an unverified engine, and do not replace 26.4.3. The most promising next proof of concept is the current LibreOffice Android source's editing-enabled flavor, because it bundles the core and contains an editing path plus some D-pad key handling. However, the exact API-21 build configuration, 2 GB RAM behavior, full TV remote usability and single-APK integration must pass tests before it can be selected for 26.5.0.
